Сонгосон үндэслэл



5 VU үед хэмжигдсэн baseline p95 latency нь 224.42 ms байсан. Лабораторийн зааврын дагуу baseline утгаа 1.5 дахин үржүүлэн SLO-оо тодорхойлсон.



224.42 × 1.5 = 336.63 ms тул p95 < 337 ms гэсэн SLO сонгосон. Энэхүү босго нь ачаалал өсөх үед гүйцэтгэл бага зэрэг муудахыг зөвшөөрөх боловч хэрэглэгчийн туршлагыг хангалттай түвшинд хадгалах боломжтой.

Дүгнэлт



Энэхүү лабораторийн ажлаар k6 хэрэгсэл ашиглан веб системийн гүйцэтгэлийг 5, 30 болон 100 виртуал хэрэглэгчийн ачаалал дээр хэмжиж шалгалаа.



Ачаалал нэмэгдэхийн хэрээр throughput мэдэгдэхүйц өссөн. 5 VU үед секундэд 7.72 хүсэлт, 30 VU үед 45.99 хүсэлт, 100 VU үед 143.69 хүсэлт боловсруулагдсан.



Latency мөн бага хэмжээгээр өссөн. p95 latency нь 5 VU үед 224.42 ms байсан бол 100 VU үед 234.52 ms болсон. Throughput огцом өссөнтэй харьцуулахад latency-ийн өсөлт харьцангуй бага байсан.



Бүх туршилтын үед error rate 0% байсан нь сервер тогтвортой ажиллаж байгааг харуулсан.



Эдгээр үр дүн нь лекц дээр үзсэн throughput болон latency хоорондын хамаарлыг баталж байна. Хэрэглэгчийн тоо өсөхөд систем илүү олон хүсэлт боловсруулах боловч хариулах хугацаа аажмаар нэмэгддэг болохыг ажиглав.



Baseline хэмжилтэд тулгуурлан p95 < 337 ms гэсэн SLO тодорхойлсон бөгөөд 100 VU хүртэлх бүх туршилтын үед энэхүү шаардлага хангагдсан.



Иймээс туршигдсан нөхцөлд систем тогтвортой ажиллаж, тодорхойлсон үйлчилгээний түвшний зорилтыг хангаж чадсан гэж дүгнэж байна.
